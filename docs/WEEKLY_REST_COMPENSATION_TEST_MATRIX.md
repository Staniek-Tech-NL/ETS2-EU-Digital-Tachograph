## Zrealizowana kolejność testów

1. `REF-01/02` potwierdziły czerwony stan `18/353`, a po zmianie algorytmu przeszły z pełnym długiem `1253/1192`.
2. `BND-01/02` potwierdziły atomowy próg: minuta za mało nie zmienia długu, dokładna wartość zamyka go w całości.
3. `BND-03/04` potwierdziły wiele pełnych zobowiązań, rozłączne zakresy spłaty i brak pomijania FIFO.
4. `BND-05A/B/C` potwierdziły ścisłą granicę `DueAtExclusive` oraz statusy `PaidOnTime`, `PaidLate` i `Overdue`.
5. `BND-06A/B` potwierdziły stabilność pełnego kontraktu po utworzeniu nowej instancji RuleEngine, przy równoważnym innym podziale historii na rekordy oraz po zamknięciu i ponownym otwarciu plikowej bazy SQLite.

Gate RuleEngine oraz integracyjny gate restartu SQLite są zielone. Application DTO mapuje pełne zobowiązania i ślad spłaty, a dotychczasowe pola zbiorcze są projekcją pochodną. Dashboard i nakładki pokazują wyłącznie podsumowanie, natomiast zakładka `Rekompensaty` prezentuje każde zobowiązanie i pełny ślad spłaty. PDF zawiera czytelną tabelę zobowiązań, CSV zapisuje jeden rekord na zobowiązanie, a JSON udostępnia pełne `CompensationObligations` obok kompatybilnego podsumowania pochodnego.
